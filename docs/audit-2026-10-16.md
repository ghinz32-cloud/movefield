## Routine audit

**68 of 125 proposed variants qualify for inclusion.** Existing 145 app definitions remain available, producing 213 app definitions alongside the existing creator-source programs. The 57 withheld variants comprise 24 that cannot retain their defining work within their stated time, seven that cannot meet the current recovery scheduling rules, and 26 requiring separate sprint/jump readiness and progression design.

The review corrected underestimated durations, unsupported recovery groups, automatic volume inflation, growing walking prescriptions, inaccurate NHS attribution and unsupported claims about exact routines. Generated data uses the actual current planner, preparation/rest/per-side duration estimates and movement accounting. Time availability is a ceiling; longer availability no longer silently adds work to the new fixed-dose variants. Accepted personal plans and stored history are not automatically rebuilt when the catalog changes.

The new routines include six-day options. Existing seven-day pathways retain lighter activity where appropriate. Personal selection still checks actual equipment, available weekdays, experience, commitments and readiness. More days do not promise more results or require seven hard lifting sessions. References support general training principles, not a clinical certification of these exact routines or an outcome guarantee.

See the [detailed routine audit](routine-library-audit-2026-10-16.md) and [all 125 individual qualification decisions](routine-library-qualification-2026-10-16.json). Focused checks exercised 855 real plan builds and 212 expected rejections. Complete training lifecycle checks covered 222 plans, 6,995 sessions, 48,414 sets and 1,999 persistence round trips.

## Exercise-library coverage and limits

The complete inventory contains 995 unique exercise IDs and 995 guides with all 14 required fields. All 1,726 local photos decode successfully; no missing, corrupt or orphan photo files were found. There are 863 exercises with photos, six with direct video URLs, and eight with a linked source page marked as video. **126 exercises lack photos or direct videos.** Three unused legacy media keys and three empty photo arrays remain minor housekeeping/coverage items.

## Web, native, security and performance findings

Detailed workstream reports: [native UI and behavior](audit-2026-10-16/native.md), [security and data integrity](audit-2026-10-16/security.md), and [baseline release/original-site audit](audit-2026-10-16-release.md). Shared snapshot checks compare all 97 canonical/native file hashes, including routine data and guides. The Android workflow now runs this parity check and the new routine, equipment and substitution checks before compiling.

Native interface tests execute actual components through React Native Web with explicit synthetic storage and OS boundaries. They do not replace installed-phone tests. Web browser checks use real encrypted records, actual built assets, quota-failure injection, save/reload, backup, navigation, guide recovery and finite rendered accessibility states. Build and test receipts distinguish these scopes.

The initial cloud test failure came from its test bundler selecting Better Auth's browser async-context fallback, causing concurrent requests to lose request state. Matching the real Worker `workerd` export condition fixed the harness; the exact single-writer conflict assertion remains. Added concurrent reads verify two owners remain separate. The production bundle already uses `node:async_hooks`.

The root production dependency audit reported zero advisories. Native dependencies retain **two unresolved upstream advisories**, affecting 43 dependency-chain entries, with no registry-provided fix: `braces` GHSA-vfj7-8cjw-p6xm and `node-forge` GHSA-86w9-cpqp-85rv. This is not 43 independently demonstrated app exploits. No downgrade, integrity bypass or warning suppression was used.

Grizzly's initial offline cache contains approximately 18.44 MB of uncompressed assets, including 11.99 MB for all 35 selectable heading fonts. Movefield's equivalent cache is approximately 6.54 MB. These figures exclude HTML and HTTP compression. Guides are deferred in the interface, but installation deliberately precaches them. Low-end phone memory, rendering, slow-network cost and optional font-cache optimization remain performance work; local desktop timings are not phone benchmarks.

## Remaining release and product gates

1. **Original website:** the root app has a different encrypted vault/schema and separate features. Its 19 checked rendered states showed an unnamed onboarding progress bar and 3.89:1 inactive Saved/Paths tab text contrast. Its exact recoverable source is documented. Replacing it with the review would risk existing records; a separate scoped legacy maintenance release or reviewed migration is required. New shared routines are not claimed to be present there.
2. **iPhone and physical devices:** no Apple membership/Mac/TestFlight setup is available. No signed iPhone app, installed-device update, VoiceOver/TalkBack, OS keyboard, safe-area, background timer, reminder, secure-store, restart, file-sharing or erasure qualification is claimed. Android files are development-signed ARM64 test installers, not store releases; downloading a new APK does not update an installed app automatically.
3. **Scientific/content depth:** 57 proposed variants are withheld; exact-routine efficacy, individual medical suitability, all exact-variation demonstrations and media-rights review remain open. The qualified additions retain explicit limits and preference/equipment checks.
4. **Connected services:** GitHub Pages has no active account/backup/coaching backend. Local backend tests do not establish live Cloudflare/Google/provider behavior, retention, billing or account deletion. Automatic background merging and unrestricted AI coaching remain outside the implemented snapshot flow.
5. **Broader product:** specialized sport/race capabilities, individualized next-block volume/source-reset review, comprehensive accessibility/Safari/device coverage and other open master-prompt requirements remain in the canonical task register. This audit does not close all six master prompts.

Build Android from an exact committed source and verify the actual package/version, historical certificate, manifest, backup resources, source/tree and downloaded bytes. Preserve owner configuration, older served chunks and the separate original root.
