The retained public release evidence does not include the exact Gradle task log or a native JUnit count, and denied artifact transport was not retried. **Do not describe that successful combined step as proof that native JUnit tests executed.** Meaningful separately invoked JS/domain/upgrade tests and types remain valid evidence at their stated scopes.

Fifty-seven focused synthetic task/XML/shell/publication-evidence fixtures pass, including empty-directory artifact ZIP transport, actual XML copying, failure preservation, missing logs and tampered provenance/counts. The publisher independently recomputes the log/XML facts and binds them to the already verified app, commit and tree before copying the structured record into public `native-build-evidence.json`. This is required for the new release contract; older published evidence remains unchanged and may omit the field. All 113 existing job/artifact/draft publisher fixtures also pass. No new CI build has exercised this addition yet, and it does not retroactively establish the old run's JUnit count or add native instrumentation coverage.

Actions are pinned to full commit SHAs. Build jobs have `contents:read`; publisher scope is `actions:read` plus `contents:write`. Both checkouts disable credential persistence. Lockfile installs use `--ignore-scripts`; the publisher validates exact source, run, workflow head, attempt selection, unique artifacts, digests, archive paths, actual APK identity/signature and immutable release/draft state before upload. Existing releases/assets are not overwritten. These are useful supply-chain controls; they do not make all build inputs intrinsically trusted.

The generated release build intentionally uses Expo's **development/test signing configuration**, and the inspected certificate matches the existing preview lineage. This preserves updates and records for the current preview identities. A public/default test key is not a private production signing authority. Production distribution requires a reviewed signing and recovery plan, secure custody, and an explicit migration/update strategy; silently changing the signer would break ordinary updates. Never ask the owner to uninstall the existing app merely to bypass a signature mismatch. Use the current manual encrypted transfer/backup flow and verify recovery on actual devices before any identity/signing migration. No private signing material was read or copied during this audit.
