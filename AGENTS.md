# User-approved working rules

These instructions apply to future work in this repository. Read `TASKS.md` and the current section of `HANDOFF.md` before changing application code. New explicit user instructions take precedence.

1. Start by verifying the repository URL, current branch, full commit SHA, upstream, GitHub review/base refs and existing staged/unstaged/untracked changes. Preserve another session's work. Do not infer branch authority from the directory name or historical handoff alone.
2. Break remaining work into small, independently testable milestones. Keep one milestone in progress at a time. Decompose broad product requirements before implementing them; a heading or placeholder is not completion.
3. For Movefield, reconcile `review-fixes` with the audit line before adding features. The recorded reconciliation is application commit `9d7c13ed6352e74c0a7766bd2d80fb524a5b709f`, with parents `cc36ff73715eec1d0e278668d2f81f11c5ba19f8` and `667a3e381035b16cb1aa611c85cdf9d143b7b835`. Recheck current refs before relying on this baseline.
4. Complete one milestone, run the checks relevant to that change, and save a recoverable checkpoint before starting another. Record failures and limits. Do not rerun broad application tests for a documentation-only change merely to imply new application validation.
5. Update `TASKS.md` and `HANDOFF.md` after every milestone with completed changes, test commands/results, unresolved problems, repository/branch/commit, exact checkpoint locations and a short continuation prompt naming the next milestone.
6. Distinguish uncommitted local work, local commits, pushed GitHub commits, merges and deployments. A local scratch directory alone is not a durable checkpoint. Never claim that saving or pushing succeeded until independently verified. For a pushed checkpoint, verify the remote head and read back the saved files at that commit.
7. Standing user authorization, 8–9 October 2026: always push completed, tested work to the existing GitHub audit branch. The owner delegates technical/destination choices and explicitly approved GitHub commit creation and this app source/audit evidence going to this repository on 9 October 2026. Do not ask for push permission again. Use the connected GitHub account when CLI authentication is unavailable, verify the resulting tree/ref and file readback, and preserve local history if connector commit metadata changes.

8. Keep changes within the user's approved scope. Routine repairs and tests may continue without asking the user to invent each prompt. Do not merge, deploy, change sharing or add services outside that scope without permission. Do not include private hosting details or credentials in public handoffs.
9. If blocked or interrupted, leave a checkpoint with the exact blocker, completed and pending work, relevant logs/tests, saved locations and the next safe action. An unavailable browser/device/connector is not a passing test. Never claim direct confirmation from bro without an actual communication result.
10. Preserve completed work and historical evidence. Resume from the verified checkpoint rather than reconstructing the project. Keep canonical shared code in `lib/` and verify the native snapshot after shared changes.
11. Continuation prompts are instructions for resuming, not an automatic chat-opening mechanism. A new conversation may require the user to paste the prompt or handoff. Do not claim a replacement conversation opened without evidence.

Repository instructions make this workflow available to future agents working here. They do not guarantee that an unrelated chat or another tool can access this repository automatically.
